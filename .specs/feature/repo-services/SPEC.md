# Goal

Permettre à chaque repository de déclarer les services qu'il expose, et générer une configuration centralisée des services pour l'ensemble des branches permettant un routage HTTP local via un proxy forge avec isolation des ports par branche.

---

# Architecture

Chaque repo déclare ses services dans `.forge/services.json` (sans port). feat-forge :
1. Scanne et génère `generated.services.json` au branchRoot avec ports assignés
2. Gère `port-allocations.json` au rootDir pour réserver les plages par branche
3. Génère `.envrc` avec variables d'environnement `REPO_SERVICE_PORT`

Chaque branche a sa plage exclusive (ex: main=3000-3099, feature/auth=3100-3199) → aucun conflit de ports.

---

# Fichiers

## `services.json` (dans chaque repo - manuel)
```json
{
  "services": [
    { "name": "backend", "type": "http", "path": "/api" }
  ]
}
```
**Pas de port** - c'est feat-forge qui l'assigne.

## `port-allocations.json` (rootDir - auto-managé)
```json
{
  "_doNotEdit": "Managed by feat-forge. Manual edits cause conflicts.",
  "servicesBasePort": 3000,
  "branchRangeSize": 100,
  "allocations": {
    "main": { "start": 3000, "end": 3099, "usedUntil": 3050 }
  }
}
```

## `generated.services.json` (branchRoot - auto-généré)
```json
{
  "_doNotEdit": "Auto-generated by 'forge services scan'. Manual edits lost.",
  "generatedAt": "2026-02-11T15:30:45.123Z",
  "repos": {
    "backend-repo": {
      "services": [
        { "name": "backend", "type": "http", "path": "/api", "port": 3100 }
      ]
    }
  }
}
```

## `.envrc` (branchRoot - auto-généré)
```bash
export BRANCH_SLUG="feature-auth"
export BRANCH_SERVICES_CONFIG="generated.services.json"
export BACKEND_REPO_BACKEND_PORT=3100
export BACKEND_REPO_BACKEND_PATH="/api"
export FORGE_PROXY_ENABLED=true
export FORGE_PROXY_PORT=8080
```

# Commands

- `forge services scan` : Découvre `.forge/services.json` et génère `generated.services.json` avec ports
- `forge services list` : Affiche les services découverts
- `forge env update` : Génère `.envrc` avec variables d'environnement
- `forge env show` : Affiche la configuration actuelle

---

# Usage Flow

1. **Chaque repo déclare ses services** : Créer `.forge/services.json` avec nom, type, path
2. **Lancer le scan** : `forge services scan` découvre tous les services et les agrège
3. **Générer l'env** : `forge env update` crée `.envrc` avec les ports et variables
4. **Source ou inspectez** : `direnv allow` pour charger automatiquement, ou `forge env show` pour vérifier

---

# Important Notes

- **Fichiers auto-générés** : `generated.services.json`, `port-allocations.json`, `.envrc` ne doivent jamais être édités manuellement
  - Contiennent un champ/commentaire `_doNotEdit` comme avertissement
  - Sont régénérés à chaque `forge services scan` ou `forge env update`

- **Isolation par branche** : Chaque branche git obtient sa propre plage de ports dans `port-allocations.json`
  - Permet de travailler sur plusieurs branches en parallèle sans conflits
  - Les ports ne change pas une fois assignés (persistent dans l'allocation)

- **Localisation des fichiers** :
  - `.forge/services.json` : À la racine de chaque repository
  - `generated.services.json` : Au branchRoot (là où feat-forge trouve les repos)
  - `port-allocations.json` : Au rootDir du projet feat-forge (à côté de `.forge-config`)
  - `.envrc` : Au branchRoot

# Acceptance criteria

- [ ] `.forge/services.json` simple et documenté (name, type, path - pas de port)
- [ ] `forge services scan` génère `generated.services.json` avec ports assignés
- [ ] `port-allocations.json` gère les plages sans conflits entre branches
- [ ] `forge env update` génère `.envrc` au format `REPO_SERVICE_PORT`
- [ ] Ports assignés séquentiellement dans la plage de chaque branche
- [ ] Services ne peuvent pas déborder de leur plage
- [ ] Tous les fichiers générés ont avertissement `_doNotEdit`
